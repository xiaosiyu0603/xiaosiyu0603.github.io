将GitHub Action产生的Hexo网站在另一仓库的GitHub Page托管

发表于 2025-06-16 更新于 2025-06-24 分类于 Blog ， Hexo ， NexT 本文字数： 1.2k 阅读时长 ≈ 4 分钟
记录在两个不同的GitHub仓库中、前者储存Hexo网站源码调用GitHub Action生成网页、后者提供GitHub Page托管的流程。

一、创造源仓库和目标仓库

  1. 创建源仓库new-test-blog-src和目标仓库new-test-blog-site；

  2. 在本地创建一个目录new-test-blog-src，运行：

  3. 在本地初始化Git仓库，并将产生的文件提交到new-test-blog-src仓库的master分支，先不要上传。

二、准备用于访问仓库的令牌

(Ⅰ) 使用Classic Personal Access Tokens

  1. 打开用户的Settings→Developer Settings→Personal access tokens→Tokens (classic)[1]；
  2. 点击Generate new token (classic)创造新的令牌，允许repo范围；
  3. 记录下令牌内容，仅显示这一次。

(Ⅱ) 使用Fine-grained Personal Access Tokens（推荐）

  1. 打开用户的Settings→Developer Settings→Personal access tokens→Fine-grained tokens[1]；
  2. 点击Generate new token创造新的令牌，进入New fine-grained personal access token页面；
  3. 在Repository access中选择Only select repositories，再选择目标仓库new-test-blog-site；
  4. 在Permissions→Repository permissions中，将Contents设为Access: Read and write；其余不用修改；
  5. 记录下令牌内容，仅显示这一次。

三、给源仓库设置变量

  1. 在源仓库new-test-blog-src中，打开Settings→Secrets and variables→Actions页面[2]；
  2. 在Variables选项卡中，点击New repository variable增加一个新的变量，名称为EX_REPO_PATH，内容为new-test-blog-site的地址，其格式为<用户名>/<仓库名>，注意不要带.git尾缀；
  3. 在Secrets选项卡中，点击New repository secret增加一个新的变量，名称为EX_REPO_TOKEN，内容为刚才创建的令牌。

五、给目标仓库设置GitHub Pages

  1. 在目标仓库new-test-blog-site中，打开Settings→Pages页面；
  2. 检查部署网站地址、源文件来源、分支是否正确，如果上一步地址设置错误则修改后重新Push；
  3. 打开部署网站地址，检查网页是否显示正常。
